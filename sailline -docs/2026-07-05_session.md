# Session summary — 2026-07-05

## What we worked on

Two defenses against the lost-race failure mode (recorder dies silently mid-race):

1. **Persistent recording sessions (mobile).** Native-uploader recordings now run with `stopOnTerminate: false` + `startOnBoot: true`, so an OS kill, swipe-away, or reboot no longer stops capture — the Transistorsoft foreground service keeps recording and POSTing with no JS above it. An AsyncStorage session descriptor (`activeSession.ts`) plus a relaunch reconciler in `RecorderContext` re-attaches the UI on next launch (or drains and stops an orphaned service whose race has ended).
2. **Dead-recorder watchdog (backend).** New Cloud Run Job `recorder-watchdog` (every 2 min via Cloud Scheduler): open race + newest track point older than 5 min → FCM push "recording stopped" to the owner's devices. First server-initiated push in the app — new `device_push_tokens` table, registration endpoints, and an FCM send service over the existing firebase-admin app.

## Decisions & rationale

- **Queue + drain over native token refresh** (user decision): after a process kill, native uploads 401 once the Firebase token expires (≤1 h); fixes queue in Transistorsoft SQLite and drain on reopen. The watchdog push is what gets the app reopened, so the two features close the loop. Wiring Transistorsoft `authorization.refreshUrl` to Firebase's securetoken endpoint deferred.
- **5-min silence threshold, 2-min cadence, separate job** (user decisions). Watchdog ignores silences >3 h — race_sweep owns those.
- **FCM direct via firebase-admin, not Expo push service** — firebase-admin is already initialized for auth; no new external dependency. Client registers the *raw* device token (`getDevicePushTokenAsync`), not an Expo token.
- **Persistence gated to native mode** — a revived js-mode service would capture into the void (no JS = no flush). js-mode descriptors are still written so an interrupted session is cleaned up, and its AsyncStorage queue drains on next manual start (existing path).
- **Redis down ⇒ watchdog sends nothing** — without dedup state, a 2-min cadence would push every tick. Silence is safer; race_sweep still backstops.
- **Notify-state recorded even at 0 delivered devices** — re-pushing into the void each tick burns FCM quota; the 15-min re-notify window retries.
- **Watchdog pushes route through the existing `race-start` Android channel** (HIGH importance, lock-screen visible).

## Technical debt flagged

- **Offline re-attach edge**: if the app relaunches over a live native session while offline *and* the cached Firebase token is expired, `start()` falls back to js mode over a native-mode service — ready(reset:true) would strip the native http config and flip stopOnTerminate back on. Narrow window; fix candidate: skip the js fallback when a native-mode descriptor is being resumed.
- **Never-started races are invisible to the watchdog**: `started_at` comes from the first telemetry flush, so a recorder that dies before any fix lands has nothing to measure silence against (the 81-min-zero-points class). T-6/T-5 auto-start notifications remain the only guard there.
- **iOS push untested/unwired** (no APNs key) — consistent with the Android-sideload-only workflow, but the `platform` column is ready.
- race_sweep ends a race at its last fix after 3 h; a watchdog-notified user who never reopens the app gets a correct sweep, so no new debt there — noted for completeness.
