## Decisions made

1. **Skip the custom Mapbox Studio style for this session.** The
   built-in Light style is "good enough for tonight" per user. The
   in-file comment flagging the deferred Studio swap remains as a
   pointer for a future session.
2. **Skip the magnetometer compass fix again.** Last session
   deferred this for race-day safety (the 90°-off heading is a
   known quirk, not a regression). Re-evaluated and held the same
   line: shipping a bearing-related change with no on-water test
   window is the wrong trade.
3. **Translate the <2-marks error in `api/routing.ts`, not in the
   hook or UI.** Same layer that already handles the 425 envelope.
   Keeps the hook ignorant of backend wording and lets future error
   rewrites live in one place.
4. **Mount-effect user-location nudge over a getCurrentPosition
   subscription.** A subscription would be more reliable but adds a
   permission flow, lifecycle ownership, and an unsubscribe path —
   too much surface area for "default first paint" polish. Last-known
   location with retry is good enough.
5. **No new tests.** Every change is either a delete (logs) or
   integration-flavored (mapbox locationManager, fastapi error
   unwrap). The matching unit test for the routing.ts unwrap is
   straightforward but not race-blocking; queued for next session.
