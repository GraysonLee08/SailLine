code path upgrades it; the telemetry handler only spawns the tactician
for `pro`/`hardware`. Grayson's account was `free` → the pipeline never
ran once, on-water or in sims. Fixed this session: his row set to
`pro` in Cloud SQL (verified via SELECT).

- `ANTHROPIC_API_KEY` **is** on the sailline-api service (secret ref).
- Migration 0021 **was** applied (`to_regclass('tactician_calls')` ✓).

So the pipeline should be end-to-end functional as of today. Next live
race is the confirmation; the new debug endpoint shows every evaluation
either way.

No migration. No mobile changes. Deploy = normal push.

### Decisions + rationale

- Trace even cooldown-skipped evaluations — an empty buffer then
  cleanly means "task never spawned" (the exact failure we just spent
  a month not seeing).
- Cooldown release on transient exits only — permanent gates keep the
  SETNX so opted-out/ended races re-check once per 180 s, not per batch.
- Near-miss numbers come from the eval context (pinching/off-pace/heel
  readable in every trace); maneuver-detector internals (layline ETA
  when not firing) deferred to the Phase B harness rather than
  rewriting 7 detectors.
- Advisor SILENT vs failure not distinguished in the trace yet — needs
  a reason threaded through `generate_call`; Phase B if it matters.

## Phase B — replay harness (built same session, after Phase A tests
passed on Windows: 881 passed after one eta-serialization fix in
trace.py)

### Files

- `backend/tools/__init__.py` — new package for desk-side tools
  (never deployed; no Redis/Cloud SQL required).
- `backend/tools/tactics_replay.py` — **new.** Replays a recorded race
  through the tactician decision sequence with a simulated clock.
  Inputs: `--export` (Cloud SQL Studio JSON: race row + track + imu +
  calibrations + wind_snapshot) or `--fixture` (committed test
  fixtures). Wind: persisted `wind_snapshot` via the existing
  `snapshot_sampler` (SnapshotWind adapter), else `--wind TWD@KTS`
  synthetic. Options: `--batch-seconds`, `--include-heel` (v1c
  preview), `--route feature.json`, `--real-claude`, `--json`,
  `--heel-report`, `-q`. Output: per-evaluation lines + exits
  histogram + per-detector fired/won/cooldown-blocked + calls
  timeline. Exit vocabulary shared with `trace.EXIT_REASONS`.
- `backend/tests/test_tactics_replay.py` — **new**, 11 tests: fixture
  loading + COG derivation, full-track coverage, pinned exits, global-
  cooldown spacing, stub-call provenance, summary consistency,
  determinism (bit-identical double run), advisor-None → silent exit,
  real-API smoke behind `SAILLINE_AI_SMOKE=1` (marked slow).

### First real result (sandbox run, Beer Can 4 fixture, 270@12
synthetic wind, 30 s batches)

163 evaluations → 135 cooldown_global / 24 no_candidates /
**4 published**: layline ×2 (eta 248 s and 294 s, sensible distances),
pinching ×2 (one true pinch delta 24.6°, one sailing_low 30.4°),
off_pace fired once and lost priority correctly. First end-to-end
evidence the detector chain produces reasonable calls on real GPS data.

### Fidelity limits (accepted, documented in the module docstring)

- Orchestration mirrors `pipeline._evaluate_inner` (~30 lines
  duplicated) rather than refactoring the live pipeline for injectable
  clock/IO; constants imported from `pipeline` so tuning changes flow
  through. Compare on any pipeline sequence change.
- No simulated advisor latency → live dropped_late caused by slow
  Claude calls won't reproduce.
- `_parse_iso` handles the recorder's variable fractional seconds
  (py<3.11 fromisoformat is strict — found by sandbox run on 3.10).
