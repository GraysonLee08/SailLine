### Decisions + rationale

- Trace even cooldown-skipped evaluations — an empty buffer then
  cleanly means "task never spawned" (the exact failure we just spent
  a month not seeing).
- Cooldown release on transient exits only — permanent gates keep the
  SETNX so opted-out/ended races re-check once per 180 s, not per batch.
- Near-miss numbers come from the eval context (pinching/off-pace/heel
  readable in every trace); maneuver-detector internals (layline ETA
  when not firing) deferred to the Phase B harness rather than
  rewriting 7 detectors.
- Advisor SILENT vs failure not distinguished in the trace yet — needs
  a reason threaded through `generate_call`; Phase B if it matters.

and per-minute cadence SQL. Findings:

1. **Tactician crash — phantom column.** All 3 evaluations died at

   **migration 0025_add_app_settings** (additive, JSONB DEFAULT '{}'),
   applied via Cloud Shell runbook.

   received ~1 fix/min (vs 60); at 1.6 kt Transistorsoft judged the
   phone stationary and sent heartbeats only. Per-mark min distance

   marks. Mark detection/stats/auto-finish all cascade from missing
   data, NOT from gate geometry. Boat-speed recording is known-good
   (Beer Can 4: 4,543 pts at 1 Hz). Walking tests need a walk-test
   location profile or on-water validation only.

## Root cause #4 (late night): locationTemplate persistence failure

Desk test + `adb logcat -s TSLocationManager` (5 min, phone stationary)
found the TRUE cause of every low-cadence native session:
`Persistence failure: Unknown template variable: speed*1.943844` —
**257 times in 5 minutes, once per dropped fix.** Transistorsoft's
locationTemplate does bare variable substitution only; the kts
conversion expression threw on every location and the plugin dropped
it BEFORE its upload queue. Only motionchange/heartbeat positions
survived → the chronic ~1 fix/min server cadence. Consequences:

- The motion-state theory (three sessions of config fixes: 06-15
  stationary fix, 07-07 watchdog) was chasing a ghost — capture was
  1 Hz the whole time (hence perfect phone-side maps), persistence ate
  it. Walking/light-air speed was never the variable.
- `tsc` can't catch it (bug inside a string); "native uploader
  validated" acceptance was too weak (some uploads ≠ full cadence).

Fix (built, pending Windows pytest + APK rebuild):
- `mobile/src/recorder/backgroundGeolocation.ts` — template sends raw
  `"sog_ms":"<%= speed %>"`; comment forbids arithmetic in templates.
- `backend/app/routers/telemetry.py` — `GpsSample.sog_ms` (m/s) +
  model validator converts to `sog_kts` server-side (sog_kts wins when
  present; >60 kt after conversion → None). Insert path unchanged.
- `backend/tests/test_telemetry_wire_contract.py` — 4 new tests pin
  the exact template-rendered row shape + conversion + precedence.

Acceptance criterion (NEW, use for all recorder work): a 5-min desk
test must produce ~60 rows/min in `track_points` — not merely "some
uploads succeed".

Unexplained loose end: red `recorder.error` showing bare counting
numbers (489→499) on the recording screen during tests — revisit
after the template fix (may disappear with it).
