# 2026-06-08 Session — mark_passes off-by-one + race-postprocess exit(2)

## What we worked on

Analyzed a "Test - Dog Walk 6.8.26" recording (studio export of the session
row + 910-point GPS track + Cloud Run logs). Two real bugs diagnosed and
fixed; one infra issue and one latent bug flagged.

### Bug 1 — race-postprocess job always exited 2 (FIXED)

`race_postprocess.main()` returns 2 only on an argparse/`UUID()` failure.
Root cause: `job_trigger.py` sent `containerOverrides.args = ["--race-id",
<uuid>]`. Cloud Run **replaces** (does not merge) the job's baseline args
`[-m, workers.race_postprocess, --race-id, PLACEHOLDER]`, so the module
selector was dropped and the container ran `python --race-id <uuid>` →
interpreter exit 2. Confirmed at the OS level and by a live manual run
(`gcloud run jobs execute race-postprocess --args="-m,workers.race_postprocess,--race-id,<id>,--force"`
→ succeededCount 1). This is why every prior race had empty `ai_summary`/
`heel_summary`/`performance_summary` (executionCount was only 2).

Fix: trigger now sends the full arg list including `-m
workers.race_postprocess`. Takes effect on the next API deploy (the trigger
lives in the API service, not the job image).

### Bug 2 — mark_passes off-by-one (FIXED by removing manual passes)

The stored passes were shifted by one and dropped a mark. Cause: two
writers on one JSONB array with incompatible index arithmetic —
- auto detector: `next_idx = len(existing_passes)` (positional)
- manual endpoint: `next_idx = max(existing_indices) + 1`
A manual "Start" tap (`source:"manual"`) mixed with the detector's own
emits pushed the auto Start emit to index 1, shifting everything down. A
faithful replay of the raw track through the v3 detector ALONE produces a
clean, correct `[0,1,2,3,4]` — so the detector was never wrong; the
dual-writer mixing was.

Decision (Grayson): a racer doesn't touch the phone mid-race, so remove
manual mark-passing entirely → single writer → off-by-one impossible.
- MarkPassControls removed entirely (no in-race mark UI).
- Missed-mark push notification kept but **informational only** (no "Mark
  as passed" action; the detector picks the mark up from the track).
- `source` field dropped (no migration — all test data, per Grayson).

## Technical debt flagged

- **Cloud Run Jobs are not in CI.** `cloudbuild.yaml` deploys only the
  `sailline-api` service and rebuilds `api:latest`/`:$SHORT_SHA`. The 19
  jobs are pinned to hand-set image tags — `race-postprocess` runs
  `sailline-api:postprocess-d2` (May 15). Worker code changes never reach
  the jobs. Recommend a job-update step or pointing jobs at `:latest`.
- **HRRR conus ingest failing** (separate, pre-existing): 1200 s timeouts
  (08:48, 18:09) and a NOAA `.idx` urlopen crash (09:07,
  `weather_ingest.py:148`). conus is the base wind region.
- **mark_passes JSONB double-encoding**: the studio export showed `marks`
  and `mark_passes` as a JSON string of a JSON array (`"\"[...]\""`). The
  mobile `coerceMarkPassArray` shim works around it; the backend
  serialisation bug is still unfixed.
